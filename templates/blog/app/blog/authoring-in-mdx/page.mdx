# {frontmatter.title}

MDX is Markdown that can hold JSX. Ordinary paragraphs stay ordinary; when a paragraph is not
enough, a component goes inline.

## Expressions

Anything in braces is evaluated while the page renders. `frontmatter` is in scope, which is why the
heading above is not typed twice:

<p className="post-note">
  Published {frontmatter.date} · {frontmatter.tags?.join(', ')}
</p>

## Components

JSX works anywhere a block does:

<aside className="post-callout">
  <strong>Rendered at build time.</strong> This aside is a React element, not HTML pasted into a
  string. It went through the same compiler as every `.tsx` file in the project.
</aside>

## Markdown that is just Markdown

GitHub Flavored Markdown is on by default — tables, task lists, autolinks, and footnotes:

| Extension | Raw HTML  | JSX |
| --------- | --------- | --- |
| `.md`     | escaped   | no  |
| `.mdx`    | evaluated | yes |

Use `.md` when the file is prose that should never execute anything, and `.mdx` when a component
belongs in the middle of it. Raw HTML written in a `.md` file stays inert on purpose.

## Shared components

To give every post the same `h2`, link, or image treatment, add `app/mdx-components.tsx`:

```tsx
export function useMDXComponents(components = {}) {
  return {
    ...components,
    h2: (props) => <h2 className="post-heading" {...props} />,
  }
}
```

The nearest provider wins, so `app/blog/mdx-components.tsx` can specialize only the posts and leave
the rest of the site alone.
