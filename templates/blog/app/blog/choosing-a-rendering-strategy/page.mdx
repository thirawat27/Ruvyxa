# {frontmatter.title}

A strategy answers one question: **when is this page's HTML produced?** Ruvyxa reads the answer out
of the route's own exports rather than a separate configuration file, so the page and its strategy
cannot disagree.

| Strategy | Declared by                               | HTML is produced              |
| -------- | ----------------------------------------- | ----------------------------- |
| SSG      | a static route, or `getStaticParams`      | at build time                 |
| ISR      | `export const revalidate = 60`            | at build, refreshed after TTL |
| SSR      | the default                               | on every request              |
| CSR      | a `'use client'` page                     | in the browser, after a shell |
| PPR      | `export const ppr = true` with `Suspense` | shell at build, slot streams  |

## What this blog uses

Every post here is a static route, so every post is SSG: the HTML is a file on disk before anyone
asks for it. That is the right default for writing. Nothing about a published post changes between
two requests, so nothing should be recomputed between them.

## When to reach for something else

- **ISR** for a page that is mostly static but reads something that moves — a view count, a list of
  recent comments. `export const revalidate = 300` serves the cached HTML and rebuilds it in the
  background after five minutes.
- **SSR** when the answer depends on _who_ is asking. A signed-in dashboard cannot be a file.
- **CSR** for a page that is entirely an application — an editor, a canvas — where server HTML would
  be thrown away on hydration anyway.
- **PPR** when one slow region sits inside an otherwise static page. The shell is pre-rendered and
  the slow part streams in behind a `Suspense` boundary.

## Checking what you got

`ruvyxa routes` prints the discovered manifest, and the build's route table marks each entry:

```bash
npm run routes
npm run build
```

If a page you expected to be static shows as dynamic, something in it reads the request. That is the
useful signal — chase it before adding configuration to override it.
